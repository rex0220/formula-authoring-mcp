# テスト用アプリとテストデータ（kintone への書き込みの唯一の例外。利用者が明示したときだけ）

formula MCP のツールは kintone に書き込まない（GET だけ）。テスト用アプリとテストデータは、Claude Code の公式の kintone MCP で、利用者が明示したときだけ行う。Claude Desktop（kintone MCP が無い）では、利用者がアプリとテストデータを作る。

**既存のアプリのテスト用アプリは AI が作らない。** 利用者に kintone の「アプリを作成 → ほかのアプリを再利用」で複製してもらう（項目・ルックアップ・関連レコード一覧・一覧・プラグインの設定まで写り、本番と同じフィールドコードになる。「データも複製」は選ばない）。計算式プラグインが写っていなければ、アプリの設定 → プラグインで追加してもらう。

**テストデータ**（利用者が「アプリ N にテストデータを入れて」と頼んだとき。Claude Code）:

1. 聞く: 件数、含める値（典型でない値: 選択肢の未選択、空の金額、同じ値の重複、該当なし、0 件）、テーブルの行数
2. `fml_fields`（app = N）で項目と型・選択肢を見て、値を**作る**（本番のレコードは写さない。個人の名前・連絡先・実在の取引先を入れない）
3. kintone MCP の `kintone-add-records` で N にだけ入れる（承認が出る。承認の画面のアプリ番号が N であることを確かめる）
4. 入れたレコード番号を伝え、`fml_record` で取って `fml_calc` に使う

**新しいアプリ**（複製元が無く、利用者が「新しいアプリを作って」と明示したとき。Claude Code）:

1. 聞く: アプリの名前、置くスペース（無ければ指定なし）、項目（要件から AI が案を表にして確かめる。フィールドコード・型・選択肢・テーブルの子）、テストデータの件数と含める値
2. kintone MCP の `kintone-add-app` で作る（承認が出る）。**返ってきたアプリ番号を控え、以後はその番号にだけ書く**
3. `kintone-add-form-fields` で項目を足し（ルックアップ・関連レコード一覧は参照先を利用者に聞く）、`kintone-update-form-layout` でレイアウト、`kintone-deploy-app` で運用環境に反映（それぞれ承認が出る。承認の画面のアプリ番号が 2 の番号であることを確かめる）
4. 上の「テストデータ」の 2〜4
5. 利用者に伝える: 新しいアプリの番号と URL、**計算式プラグインをアプリの設定 → プラグインで追加してもらう**（MCP にはそのツールが無い）、接続のファイルの profile の `tokenMap` にそのアプリのトークンを足してもらう（AI は接続のファイルを書かない）、以後の作業はこの番号で行う
6. `fml_fields` で項目を取ってから設定を作る

既存のアプリ（本番のアプリを含む）の項目・レイアウト・反映には、これらのツールを使わない。
