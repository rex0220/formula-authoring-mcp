# 計算式の制約（守らないと動かない・壊れる）

- **封筒なし（素の設定だけ）の JSON は誤り。** `pluginID`（`"rex0220 formula plugin"`）/ `PluginVersion` が違うと取り込めない。雛形は sample-settings の章
- 計算式には**フィールドコード**を書く（ラベルではない）。テーブルの子の項目はテーブルの中の式ではそのまま、テーブルの外の式では集計関数（SUM(テーブルの子) など）で参照する
- `//` から行末まではコメント。**文字列の中の `//` も行末までコメントになる**（`"https://…"` を書かない）。改行は実行時に無視される（見やすさのために入れてよい）
- 文字列は `"…"`。`\n` は改行にならない（`\` を解釈しない）。改行は `NEWLINE()`
- **`&` は関数の結果の前後の空白を落とす**（`"sun" & IF(x, " today", "")` → `suntoday`。文字列と項目の空白は残る）。空白ごと返すなら値の全体を 1 つの文字列にする（`IF(x, "sun today", "sun")`）か `CONCAT` でつなぐ
- **`LET` は 1 つに変数を並べる**（`LET(a, 式a, b, 式b, 結果)`。後の式で前の変数を使える）。入れ子（`LET(a, …, LET(b, …))`）も動くが読みにくいので、`ARRAY_FOR` などの中で変数が要るときだけに
- **計算の順はランク**（-10000〜10000。**大きい順**。未設定は 0。同じならレイアウトの順）。ランクなしの計算順は、テーブルの外の項目（1 回目）: 上から下、同じ行では左から右 → テーブルの中の項目: 左から右 → テーブルの外の項目（2 回目）: 上から下、同じ行では左から右。この順で合うなら付けない（例: 数量・単価 → その右の金額、テーブルの金額 → テーブルの外の金額合計）。参照される項目が後ろにあるときだけ、参照される項目に大きいランクを付ける（例: 右の項目を参照する左の項目なら、右に 2、左に 1）。設定画面は自己参照と 2 項目の相互参照を止める（`circular_refer` が OFF）。計算は 3 段（テーブルの外 → テーブルの行 → テーブルの外をもう一度）なので、順が逆でも 2 段目で追いつくことがあるが、頼らない
- テーブル自身に計算式を置くと**行数の制御**（行数 | 初期データ）になる。テーブルの子に置くと行ごとに計算する（書き方は patterns の章）
- 副作用のある関数は BUTTON / DIALOG の中で使う。formula MCP は policy の承認が無ければ評価しない（AI は policy を書かない）
- イベントで結果が変わる式（`EV_INFO("type")` など）は、どのイベントでどの値になるかを表にして利用者に示す。「既存レコードを変更」は `allUpdate`、一覧の「一括計算」は `batch` のイベントで動く（画面の入力時と同じにならない）
- 一覧 ID、権限のコード、ルックアップ先のアプリ番号は推測しない（利用者に聞く）
- 内部番号（fieldno / tableno）は設定画面が保存時に補う。formula MCP の出力には無い（正しい）
- `fml_update_fields` の rows には元の値（`fieldcode`、`state`、`formulaSet`、`edit`、`hide`、`rank`）だけを書く。画面の値（type、fieldlabel など）は normalize が項目定義から補う。設定に無い fieldcode には足せない（項目はアプリの項目定義で決まる）
