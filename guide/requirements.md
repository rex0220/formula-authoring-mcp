# 要件を AI が作る（利用者のやりたいことが短いとき）

利用者が「アプリ N の … を集計したい」のように短く伝えただけなら、設定を作る前に**要件を `requirements/<アプリ名>.md` に書いて利用者に確かめる**（`requirements/` は AI が Write で書いてよい）。

1. `fml_fields`（app）で項目（フィールドコード、型、テーブルの子、選択肢）を見る。代表のレコードの形は `fml_record`（値は返らない。形だけ）
2. 決めるべき点を表にして聞く（howto-new の「仕様の確認」と同じ観点: 該当の無い分類の行を出すか、行の順、空のときの値、端数、既存の入力値を上書きしてよい項目か、ボタンか自動か、どのイベントか、テストのレコードに無いが起こりうる値の扱い）。patterns の章に同じ目的の別のやり方があれば、結果の違いを添えて選んでもらう
3. 答えをもとに要件を書く（アプリ番号と名前、項目の対応、番号付きの要件、決めた点、未決の点）。要件はフィールドコードでなく**利用者の言葉（ラベル）**で書き、どのコードに当たるかは括弧で添える
4. 利用者が読んで OK を出してから howto-new に進む（howto-new の 4 の仕様の確認は、ここで済んだ分を繰り返さない）

要件の例（テーブル内集計）:

```
# アプリ 2305 テーブル内集計

## 項目の対応
- 明細（テーブル: テーブル）の 分類（分類）、商品（商品）、数量（数量）、単価（単価）、金額（金額）
- 合計（金額合計）

## 要件
1. 明細の行が「明細」のとき、金額 = 数量 × 単価。「小計」のとき、金額 = 直前の小計からその行までの「明細」の金額の合計
2. 合計 = 「小計」の行の金額の合計

## 決めた点
- 空の数量・単価は 0 として計算する
- 既存の金額の入力値は上書きしてよい

## 未決の点
- 端数（今は整数のみ）
```
